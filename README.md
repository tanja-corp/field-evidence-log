# Field Evidence Log

インターンで確かめたこと、分かったこと、そこから得た学びを1か所にためるダッシュボード。
まず月例のAdmin Meetingの発表資料を支え、のちに最終成果発表、ES、面接の素材としても使う。

公開ページ（GitHub Pages）: https://tanja-corp.github.io/field-evidence-log/

> **公開ページです。** 検索に出ない設定（noindex）にしているが、URLを知っていれば誰でも読める。
> 書いてよい範囲は、末尾の「守ること」を見る。

## 何が見られるか

| 画面 | 中身 |
|---|---|
| 概要 | 件数、答えてほしい問い、予定、最近の更新 |
| 構成と時間 | Admin Meetingのスライドごとの狙い・中身・読み上げ時間。スライドごとにOK／直す／保留を返せる |
| 記録 | 経験を1件ずつ。状況・したこと・分かったこと・学び、出典、足りない材料 |
| 学び | 複数の記録に共通する学びのテーマ |
| 面接素材 | ガクチカ・面接用の下書き。確度タグつき |
| 入力する | 入力の3つの方法 |
| 進め方 | 回し方、確度のルール、公開ページで守ること |

## 入力の方法

1. **フォーム**：「入力する」画面から、GitHubのIssueフォームを開く。送ると、Actionsが検査してJSONに追記し、サイトを更新する（1〜2分）。
2. **Claudeに話す**：箇条書きでよい。Claudeが `scripts/add_entry.py` で記録し、検査を通して push する。
3. **直接編集**：`data/entries.json` を編集して push。`scripts/validate.py` が通らないと公開されない。

## フィードバックの方法

「構成と時間」「概要」「記録」「面接素材」のボタン（OK／直す／保留）から、フィードバックのフォームを開く。
送ると `data/feedback.json` に入り、画面に反映される。Claudeは次の作業の前に、これを読んでから資料と記録を直す。

## データ

`data/` のJSONが元データ。画面はそれを読むだけ。

| ファイル | 中身 |
|---|---|
| `deck.json` | 発表スライドの構成、狙い、秒数、原本からの変更 |
| `entries.json` | 経験の記録 |
| `themes.json` | 学びのテーマ |
| `interview.json` | ガクチカ・面接の下書き |
| `questions.json` | 答えてほしい問い |
| `feedback.json` | フィードバックの記録（自動で追記） |
| `changelog.json` | 更新の履歴 |
| `config.json` | リポジトリ名、予定、ラベル |

## 就活の台帳との関係

記録の確度は、就活用の台帳（非公開）と同じ4つのタグで表す。✅は確定、⚠️は要確認、💭は構想・進行中、⏸は停止。
確定回答に使ってよいのは✅だけ。記録は⚠️から始め、数字・出典・自分の役割がそろったら本人の確認で上げる。
台帳に貼る形の候補は `python scripts/export_facts.py` で出る。

## ローカルで見る

```
python -m http.server 8000
```

ブラウザで http://localhost:8000 を開く。データの検査は `python scripts/validate.py`。

## 守ること

- 個人名、取引先名、金額、社内の非公開の情報を書かない。
- 数字は公開資料のものを使い、出典をつける。
- 同僚の成果は、自分の役割が確認できるまで自分の実績にしない。
- `scripts/denylist.local.txt`（git管理外）に、公開してはいけない語を書いておくと、`validate.py` が弾く。
